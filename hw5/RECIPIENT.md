# Проверка готового ДЗ 5 и запись видео

Архив содержит исходный код, `uv.lock`, токенизированные данные, оба обученных
LoRA-адаптера, метрики, график и отчёт. Виртуальное окружение `.venv` не входит:
оно зависит от системы, поэтому создаётся на вашем ноутбуке. Базовые веса
`Qwen/Qwen3-0.6B` также не входят; при первом `make check` они загружаются из
Hugging Face (нужен интернет и свободное место). Затем `make check` пересчитывает
пять эталонных ответов на вашем устройстве: жадная генерация на разных GPU
может дать немного разный текст. Проверка переноса адаптера после этого
запускается без сети.

## Linux или macOS

Установите `uv`, `make` и `bash`, откройте терминал в папке `hw5` из архива:

```bash
uv sync
make check
```

На видео покажите команду `make check`, все девять зелёных пунктов, строку
`Все проверки пройдены` и отпечаток `tests/check.sh` в конце. Ожидаемый
отпечаток исходного проверочного скрипта: `06a02208c1f0`.

## Windows

Запускайте те же команды в WSL или Git Bash с установленными `make`, `bash` и
`uv`: проверочный скрипт использует Unix-утилиты. В WSL распакуйте архив в
его файловую систему; в Git Bash откройте папку `hw5` на диске Windows.
Выполните `uv sync`, затем `make check`.

## Железо и время

`model.device: auto` выбирает CUDA на NVIDIA, MPS на Mac и CPU иначе. Конфиг
использует `bfloat16`; для NVIDIA проверьте поддержку этой точности до запуска:

```bash
uv run python -c "import torch; print('CUDA:', torch.cuda.is_available()); print('BF16:', torch.cuda.is_bf16_supported() if torch.cuda.is_available() else 'нет CUDA')"
```

На CPU проверка, особенно два коротких обучающих прогона в пункте 5, может
занять значительно больше времени. Не меняйте `params.yaml` или код перед
видео: проверка сверяет отпечаток настроек и кода с уже обученными адаптерами.
Если пункт 4 всё же упал, передайте автору задания строку ошибки под ним:
она покажет, не упёрлась ли машина в память или установку PyTorch.
