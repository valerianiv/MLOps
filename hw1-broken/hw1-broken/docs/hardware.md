## Найденные и исправленные дефекты

### 1. Имя модели захардкожено в коде

**Где было:** `src/generate.py` и `src/bench.py`

**Как проявлялось:** При смене модели в `params.yaml` код продолжал использовать старую модель `Qwen/Qwen3-0.6B`.

**Как исправила:** Заменила `"Qwen/Qwen3-0.6B"` на `params\["model"]\["name"]` в обоих файлах.



### 2. Зависимости без версий

**Где было:** `pyproject.toml`

**Как проявлялось:** Без фиксации версий проект не воспроизводим на других машинах — разные версии библиотек могут давать разное поведение.

**Как исправила:** Добавила версии для всех зависимостей:

- `torch>=2.1.0`

- `transformers>=4.36.0`

- `accelerate>=0.25.0`

- `numpy>=1.26.0`

- `pyyaml>=6.0`

- `psutil>=5.9.0`



### 3. Неправильный замер скорости

**Где было:** `src/bench.py`

**Как проявлялось:** Время загрузки модели включалось в замер скорости, не было прогревочного запуска (warmup). Кроме того, использовался модуль `resource`, который недоступен на Windows.

**Как исправила:**

- Разделила замеры: отдельно загрузка модели, отдельно прогрев (не учитывается), отдельно измерение скорости.

- Заменила `resource` на `psutil` для кроссплатформенного замера памяти.

- Добавила вычисление медианы вместо среднего для устойчивости к выбросам.

### 4. Недетерминированность

**Где было:** `src/generate.py` и `src/model.py`

**Как проявлялось:** При `temperature = 0.7` ответы были разными при каждом запуске.

**Как исправила:**

- Выставила `temperature: 0.0` в `params.yaml` (что отключает сэмплинг).

- Добавила фиксацию seed через `set_seed()` в `model.py`:

   ```python

    random.seed(seed)

    np.random.seed(seed)

    torch.manual_seed(seed)
   ```

## Тема датасета для ДЗ3:
Для выполнения третьей домашней работы я планирую использовать связку датасетов для задачи исправления грамматических ошибок в русском языке (Grammatical Error Correction, GEC).

Для обучения (SFT): датасет SyntErr v4. Он содержит 39 209 синтетических примеров ошибок, размеченных по 48 грамматическим правилам из LORuGEC. Это позволяет обучить модель на достаточно большом объёме данных без необходимости ручной разметки.

Для оценки качества: датасет LORuGEC. Он включает около 1000 размеченных предложений (348 для валидации, 612 для теста) и создан исследователями МГУ и Яндекса. LORuGEC специально разработан как диагностический набор, чтобы проверять, как модель справляется с конкретными типами ошибок.

#### Обоснование выбора
Реалистичный объём обучения. SyntErr v4 даёт достаточно данных (39k примеров), чтобы модель научилась исправлять ошибки, но при этом не перегружает ноутбук (16 ГБ ОЗУ, CPU).

Качественная оценка. LORuGEC позволяет точечно проверить, какие правила модель усвоила, а какие — нет.

Академическая значимость. Оба датасета созданы на базе МГУ и Яндекса, а работа по LORuGEC представлена на конференции ACL 2025, что говорит об их научной обоснованности.
